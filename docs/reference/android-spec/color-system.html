Usage: keep #1A3D26 and #E3E5E3 for normal text on their respective surfaces. Use the primary color for actions and emphasis. Borders are subtle separators; use primary for an edge that must stand out. White is shared for high-emphasis icons/highlights and light elevated surfaces. On a dark primary fill, use the dark surface color for labels and icons.
Contrast check: light primary on its surface is 4.09:1, so reserve it for accents or controls rather than small body text. White content on the light primary is 4.85:1. White on the dark primary is only 3.09:1; dark surface content on it is 5.99:1. The selected borders are intentionally low contrast: 1.08:1 in light mode and 1.97:1 in dark mode.

Consolidation opportunities

Candidates to simplify the source palette while preserving clear visual roles.

Review before changing app code
Reuse exact semantic colors

Home accent, goal accent, and chip values already match the theme’s sage tokens. The light splash also matches the light surface container value.

Share repeated reader backdrop

Ritual and wird reader use the same three dark gradient stops. Keep one named screen token source for both surfaces.

Review near-white surface pairs

#F0F2F0 / #F1F3F1 and #FCFDFC / #FDFEFB are close. Compare actual component hierarchy and contrast before merging.

Consolidate light home card tints

Dawn, day, dusk and night cards use four subtle, translucent near-white fills. A shared card token could reduce drift if time-of-day tint is not intentional.

Audit ad-hoc text and border colors

Home uses custom text and border colors such as #103C1D, #656763 and #E0E6D6. Map these to semantic roles where contrast remains suitable.

Confirm unused template values

Verify XML resource references/build variants before deleting purple and teal resources. Keep launcher and notification colors tied to their asset needs.

Keep distinct: error colors, on-color pairs, and neutral tonal steps have different contrast jobs. Do not merge them only because their hues look similar.
