Awrad auth / system flows

A stronger auth story, end to end.

One account identity, a frictionless web entry point, and explicit mobile readiness. These flows show how magic links, passwords, sessions, recovery, and synced practice fit together.

01 / sequence

From account creation to mobile-ready

Web access stays magic-link-first. Android receives a clear setup path when the account has no password yet.

02 / architecture

One identity, two session surfaces

The browser and mobile clients use different session mechanics, but converge on one verified scope and one canonical progress write path.

03 / state machine

Passwordless is valid; mobile readiness is explicit

The account does not need a password to be useful on the web. A password or passkey is a separate capability required for password-based mobile login.

Product rule

Magic-link web access stays frictionless. Password or passkey setup is required only when the user enables password-based mobile login and sync.

Session rule

Web uses a host-only cookie. Mobile uses a short-lived access token plus rotating refresh token. Both resolve to the same verified user scope.

Recovery rule

Setup and reset links are single-use. Password reset revokes sessions, and the security surface shows active devices and audit events.
