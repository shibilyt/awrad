# Decision: JWT Access Tokens with Joken

## Status

Accepted

## Date

2026-04-07

## Context

The mobile API needs a way to authenticate each request without hitting the database. Access tokens are sent with every API call, so they need to be fast to verify.

## Decision

Use **Joken** to sign HS256 JWTs as access tokens. Tokens are:

- Signed with a per-environment secret (`config :awrad_server, AwradServer.Accounts.Token, signing_secret: ...`)
- 15-minute expiry
- Contain only `sub` (user UUID) as a custom claim
- Standard claims: `iss`, `aud`, `exp`, `iat`, `nbf`, `jti` (auto-generated by Joken)

Verification is a pure function — no DB call, no network call.

## Alternatives Considered

### Guardian

Rejected. Guardian is a full auth framework with token serialization, permissions, hooks. We only need JWT signing/verification — Joken is lighter and more explicit.

### Phoenix.Token

Considered. Built into Phoenix, simple signing. But no standard JWT claims (`exp`, `iss`, `aud`), no interoperability with mobile JWT libraries, and no automatic expiry enforcement.

### Database tokens (like session tokens)

Rejected for access tokens. Every API call would require a DB query. Acceptable for refresh tokens (used rarely), not for access tokens (used on every request).

## Consequences

- Joken is a small dependency (+ JOSE for crypto)
- Access tokens cannot be revoked before expiry — this is acceptable because they're short-lived (15 min)
- The mobile app must handle 401s by refreshing tokens, not by relying on token revocation
